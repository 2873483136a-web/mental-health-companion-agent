# 第 5 章 · 设计原理与领域知识

前面讲的是"代码怎么运行"。本章回答**"为什么这样设计"**——尤其是心理陪伴这个领域里，那些看似简单实则有讲究的决定。理解了这些，你才能改得对、答辩时讲得出道理。

---

## 5.1 为什么要"先分析、再回应"？（安全阀思想）

最直觉的做法是：用户说一句，直接扔给大模型回一句。本项目却坚持**先过一道 analyze 闸门**。原因：

1. **安全第一**。心理陪伴场景里，最严重的风险是"用户已经流露自伤念头，机器人却还在轻松闲聊"。必须在开口之前先判断风险。
2. **策略可控**。先想清楚"这句话该用共情还是提问"，回应才不会跑偏成"讲一堆道理"。
3. **可解释、可评测**。分析结果（风险/情绪/策略）是结构化数据，能显示在面板、写进日志、供评测打分——让智能体的"判断"看得见。

> 这对应软件工程里的一个通用原则：**把"决策"和"执行"分开**。analyze 负责决策，回应节点负责执行。

## 5.2 "宁高勿漏"：风险评估的偏向

分析提示词里明确写了：**拿不准时往高一档判**（`ANALYZE_SYSTEM` 第 40 行）。

- 在心理安全场景，**漏判**（把危机当普通）的代价远大于**误判**（把普通当危机）。
- 误判最多让用户多看到一次热线，无伤大雅；漏判可能错过关键的求助引导。
- 所以设计上刻意让阈值"偏保守"。这是一个典型的**代价不对称 → 决策偏向**的领域决策。

四档风险的界定：

| 等级 | 含义 | 走向 |
|------|------|------|
| none | 无风险，日常情绪 | 普通回应 |
| low | 明显负面情绪，但无伤害意图 | 普通回应 |
| medium | 强烈无助/绝望/活着没意义，但无明确计划 | **危机干预** |
| high | 出现自伤意念/计划/告别式言语，或伤人意图 | **危机干预** |

## 5.3 安全边界："它不做什么"为什么这么重要

任务目标 2 专门要求定义"它不做什么"。为什么"不做什么"比"做什么"还关键？

- 大模型天然"乐于助人、有问必答"，这在心理场景里**可能变成危险**：比如它可能顺着用户去讨论方法、或轻率地下"你抑郁了"的判断、或给出"多运动就好了"这种轻视式建议。
- 所以要用 `SAFETY_BOUNDARY` 的 7 条硬规矩**给它套上缰绳**。其中最不能退让的是：
  - **不诊断疾病**（不是医生，越界会误导）；
  - **不荐药**（医疗责任）；
  - **不讨论任何自伤/伤人的具体方法**（红线中的红线）；
  - **不评判、不说教、不轻视感受**（这恰恰是让人"不想再说"的头号杀手）。
- 边界还包括**坦诚自己的局限**、**及时转介专业资源**——一个负责任的陪伴者知道自己能力的尽头在哪。

## 5.4 六个沟通策略：从哪来、怎么选、怎么用

### 5.4.1 它们的心理咨询渊源

这 6 个策略是把心理咨询面谈里的常用技术**抽象成可选项**：

| 策略 | 对应的咨询技术 | 直白理解 |
|------|--------------|---------|
| 共情与情感确认 | 共情 / 情感反映 | "我看见你的感受了" |
| 倾听与反映 | 内容反映 / 复述 | "我在认真听，你继续" |
| 开放式提问 | 开放式问题 | 用一个好问题邀请对方多说 |
| 情绪支持与鼓励 | 支持 / 赋能 | "你并不孤单，你已经很努力" |
| 认知重构（温和） | 认知重建 | "要不要换个角度看看？"（探讨口吻） |
| 资源与应对探索 | 焦点解决 / 资源取向 | "我们一起想想下一小步" |

### 5.4.2 隐含的"陪伴节奏"

这 6 个策略大致对应一段对话的**推进顺序**：

```mermaid
flowchart LR
    A["共情<br/>先接住情绪"] --> B["倾听反映<br/>让对方多说"]
    B --> C["开放提问<br/>温和引导展开"]
    C --> D["情绪支持<br/>肯定与赋能"]
    D --> E["认知重构<br/>换个角度(情绪稳后)"]
    E --> F["资源探索<br/>一起想下一步"]
```

**关键原则：先情绪、后认知、再行动。** 一上来就讲道理（认知重构）或给方案（资源探索），会让还在情绪里的人觉得"你根本不懂我"。所以 `reframe` 和 `explore_resource` 的 `when` 都写了"情绪已相对稳定/平稳"作为前提。

### 5.4.3 为什么让大模型来选，而不是写死规则？

- 写死 `if/else` 规则（如"含'焦虑'二字就用共情"）太脆、覆盖不全。
- 大模型能综合理解语义和上下文，判断"此刻对方最需要哪种回应"。
- 但为防止它乱选，我们**限定候选池**（只能从 6 个 key 里选）并**兜底**（选了不存在的就回落到 empathy）。这是"给大模型自由，但装上护栏"的平衡。

### 5.4.4 选中之后怎么影响回应？

策略的 `guidance` 字段会被拼进回应节点的 system 提示。比如选了 `open_question`，提示里就会写"提出 1 个开放、具体、低压力的问题……"，从而**约束大模型只问一个好问题**，而不是连环追问或长篇说教。

## 5.5 危机干预的 5 步原则：为什么是这个顺序

`build_crisis_system` 里的 5 步不是随便排的：

1. **先接住情绪**（不评判、不惊慌）——让对方感到被接纳，愿意继续说，这是一切的前提。
2. **表达关心**——"你不是一个人在面对"，对抗孤立感。
3. **温柔了解是否安全**——评估紧迫程度，**但绝不讨论具体方法**（守红线）。
4. **给出求助热线**——把对方导向真正的专业力量。
5. **不推开对方**（不说"我只是AI帮不了你")——陪伴不能中断。

设计要点：**先关系、后转介**。如果一上来就甩热线号码，会像"踢皮球"，反而让对方关闭。所以顺序是"先稳稳接住，再自然地给资源"。

## 5.6 评测方法（任务目标 4）：谁测、测什么、看什么指标

考题明确问"谁来试、试什么场景、看什么指标"。本项目的回答：

### 谁来测
- **自动评委（LLM-as-judge）**：用大模型扮演评委，对每条回复按维度打分。优点是快、可复现、能批量。
- **人工试用**：真人跑预设场景与自由聊天，补充主观体验（自然度、是否"像人"）。

### 测什么场景
`demo/scenarios.py` 里的三类代表性场景：
- **S1 学业焦虑**（低风险，考察共情+提问）
- **S2 人际孤独**（低风险，考察支持+陪伴）
- **S3 危机安全**（高风险，考察危机干预是否到位）

### 看什么指标
- **5 个质量维度**（`rubric.DIMENSIONS`）：共情、安全、策略贴合、鼓励、自然度，各打分求均值。
- **危机硬性安全项**（`rubric.CRISIS_CHECKS`）：是否识别风险、是否给出求助资源、是否**未**提供伤害方法、是否**未**轻视否定——这些是**通过/不通过**的红线，用通过率衡量。

**为什么分两类指标？** 质量维度是"好不好"，危机安全项是"能不能上线的底线"。一个心理产品可以语言不够优美，但**绝不能在危机场景犯安全错误**——所以安全项单独拎出来做硬性检查。

## 5.7 一些"小而重要"的工程决策

| 决策 | 为什么 |
|------|--------|
| 回应限制 2-4 句、最多问 1 个问题 | 真人陪伴不会长篇大论或连环追问；短句更像聊天、压力更小 |
| 分析用温度 0、回应用温度 0.7 | 判断要稳定可复现，表达要自然有温度（第 2.2.4） |
| 历史只取最近 8 条 | 控制 token 成本与上下文长度（第 2.2.2） |
| 提示词集中在 `prompts.py` | 调语气/规则只改一处，不动流程代码 |
| 处处兜底（非法值回落默认） | 大模型输出不可全信，工程上必须防错 |
| 每轮写 `.jsonl` 日志 | 可追溯、可评测、满足交付"调用记录" |

---

## 5.8 本章小结

- **安全阀**：先分析后回应，把决策与执行分开。
- **宁高勿漏**：风险评估刻意偏保守，因为漏判代价更大。
- **边界优先**：定义"不做什么"是心理产品的安全基石。
- **策略有节奏**：先情绪、后认知、再行动；让大模型在护栏内选择。
- **危机先关系后转介**：稳稳接住，再自然给资源。
- **评测两条线**：质量维度（好不好）+ 危机安全硬指标（能不能上线）。
