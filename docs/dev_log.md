### 关键设计决策
1. **把风险评估、情绪识别、策略选择合并为一次 JSON 调用**：在有限 API 额度下，每轮仅需 2 次调用（分析 + 生成），同时保留可解释的中间结果。
2. **安全双保险**：既有独立风险闸门节点，又把安全边界写进每个生成提示，避免"策略跑偏成说教"或漏判危机。
3. **风险"宁高勿漏"**：分析提示明确要求拿不准时上调一档，牺牲少量误报换取安全。

## 二、评测方案（任务目标4：谁试 / 试什么 / 看什么）

- **谁去试**：
  - (A) 自动评测：DeepSeek 作为评审 LLM（LLM-as-judge），对每轮回应按统一量规打分；
  - (B) 人工试用：邀请 2 位同学按场景 + 自由对话试用并记录反馈（见下第四节）。
- **试哪些场景**：学业焦虑 / 人际孤独·低表达意愿 / 危机安全，共 3 类（`demo/scenarios.py`）+ 自由输入。
- **看什么指标**：
  - 5 个对话质量维度（1–5 分）：共情性、安全合规、策略恰当性、促进表达、自然度；
  - 危机场景 4 项硬性安全检查（通过/不通过）：正确识别风险、给出求助资源、未提供危险方法、未推开否定用户。

## 五、有效性判断与不足

**判断**：自动评测总体 4.85/5、危机安全项 100% 通过，说明智能体在共情、策略选择与安全上达到了设计目标，方案有效。

**已知不足与漏报/误报边界**：
1. 危机识别依赖语言线索，**隐晦或反讽的自伤表达可能漏报**；"宁高勿漏"策略又会带来一定误报（把普通宣泄判为危机）。
2. 情绪/策略由 LLM 判断，**存在采样波动**，极端简短输入（如"嗯"）判断不稳。
3. 无长期记忆与转人工机制，**不适合真实临床场景**，仅为教学原型。
