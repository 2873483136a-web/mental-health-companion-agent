# 方案设计文档 —— 心理陪伴智能体「小屿」

## 一、需求与定位

面向**学生群体**的心理陪伴对话智能体。区别于一般对话任务，心理陪伴需要：
1. 理解并接纳情绪（而非急于解决问题）；
2. 依据心理咨询与沟通策略组织回应；
3. 针对学生"表达意愿不足、难以直接描述困扰"的特点，降低表达压力、引导开口；
4. 满足较高的安全性要求：明确的角色定位、回应边界与危机处置。

## 二、同类智能体调研与取舍（方案要求技术向1）

| 产品 | 角色与边界设计 | 优点 | 不足 | 我们的取舍 |
|------|--------------|------|------|-----------|
| **Replika** | 定位为"AI 朋友"，强调陪伴与拟人关系 | 陪伴感强、记忆连续 | 边界模糊，曾出现不当亲密/危险建议；危机处置弱 | 借鉴其陪伴语气与连续记忆；**强化安全边界与危机路径** |
| **Character.AI** | 开放角色扮演 | 角色多样、对话自然 | 无心理专业约束，易越界；未成年人保护争议 | 只借鉴自然语气；**不做开放人设，固定"陪伴者"单一角色** |
| **Woebot（CBT 类）** | 定位明确的"情绪健康助手"，强调非诊断声明 | 安全边界清晰、有循证方法（CBT）、危机转介 | 偏脚本化、灵活性差、共情感偏弱 | 借鉴其**明确的非诊断声明与危机转介**；用 LLM 增强共情与灵活性 |

**取舍结论**：采用 **Woebot 式的安全严谨 + Replika 式的陪伴温度** 组合——固定单一"陪伴者"角色（小屿），语气温暖口语化；同时把"不诊断、不荐药、不替代专业、危机转介"写死进系统提示，并用独立的风险评估节点做硬保障。

## 三、核心方案设计（方案要求技术向2）

### 3.1 角色设定与语气
- **角色**：小屿，温和、真诚、值得信任的陪伴者与倾听者，不是权威或说教者。
- **语气**：口语化、平和、有温度、多用短句，像耐心的朋友/学长学姐。
- 见 `src/prompts.py::PERSONA`。

### 3.2 安全边界（它不做什么）
7 条硬性边界（不诊断、不荐药、不替代专业、不评判说教、不打探隐私、不给危险方法、坦诚局限），见 `src/prompts.py::SAFETY_BOUNDARY`。安全边界写入**每一个生成节点**的系统提示，且由独立的 `analyze` 节点先做风险闸门，双重保障。

### 3.3 心理对话策略选择机制（任务目标3）
将心理咨询常用技术抽象为 6 个可被"按场景选择"的策略（`src/strategies.py`）：

| 策略 | 适用场景 |
|------|---------|
| 共情与情感确认 | 明显负面情绪，需先被理解接纳 |
| 倾听与反映 | 在叙述/倾诉，诉求尚不清晰 |
| 开放式提问 | 表达意愿低、信息笼统，需引导展开 |
| 情绪支持与鼓励 | 自我怀疑、无力，需被肯定 |
| 温和认知重构 | 存在绝对化/灾难化想法且情绪已稳 |
| 资源与应对探索 | 情绪平稳，开始想"怎么办" |

**选择机制**：`analyze` 节点在一次结构化 LLM 调用里，结合对话历史与最新一句话，输出 `{风险, 情绪, 强度, 策略, 理由}`。生成节点再把选中策略的"执行要点"注入系统提示，约束回应不跑偏。这样既低成本（每轮 2 次调用），又让策略选择过程**可解释、可评测**。

### 3.4 危机干预路径
`analyze` 判定 `risk ∈ {medium, high}` 时路由到 `crisis_response`：稳稳接住情绪 → 表达关心 → 温和确认安全（不给任何方法）→ 明确转介热线与身边信任的人。见 `src/prompts.py::build_crisis_system`。

## 四、技术选型

- **LLM**：DeepSeek（`deepseek-chat`，OpenAI 兼容接口）。分析节点用 `temperature=0` + JSON 模式保证稳定结构化；生成节点用 `temperature=0.7` 保证语言温度。
- **编排**：LangGraph 状态图 + 条件路由 + `MemorySaver` 多轮记忆。选择 LangGraph 是因为心理陪伴天然是"感知→决策→回应"的有状态多节点流程，图结构让**安全闸门、策略选择、回应生成**解耦、可视、可扩展。
